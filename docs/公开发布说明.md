## v2.0.0-rc.2 源码中的六项修复

本版本源码包含 Application 注册示例、异常完整类名查询、Android 导出可写路径、控制台动态开关与输出策略、两端初始化 Javadoc，以及库 Manifest 的宿主备份属性兼容修复。旧 `v2.0.0-rc.1` 仍含这些问题，其标签与旧制品保持不变。版本内容见[CHANGELOG](../CHANGELOG.md)，新版本验证不得复用旧版本结论。

- Android 初始化在已经注册的 Application 中进行；新 `MyApp` 必须配置宿主 `android:name`。已有 Application 合并调用，不能仅新增一个未注册类。
- 异常查询使用 `NullPointerException.class.getName()`，与记录的完整类名一致。Android 导出使用 `new File(context.getFilesDir(), "logs.json").getAbsolutePath()` 并在后台线程执行；Desktop 单独选择业务可写路径。
- `LogManager` 统一按次捕获 `consoleEnabled` 与 formatter；平台注入 `IConsoleOutput`，不再默认装饰数据库或强制关闭核心开关。初始 true／false 均支持双向更新，自定义 formatter 用 TXT，null 保留平台默认文本。
- 控制台保留 tag、级别、FATAL 与 stderr 路由；引擎提交后在调用线程同步输出。输出不代表落盘，普通 `RuntimeException` 记录 warning 且不回退重复输出；关闭后不再新分发，在途可完成，关闭不等待控制台。
- 宿主可明确配置 `allowBackup=true`、`false` 或省略；库不替宿主决定备份策略。这里只检查合并结果，不执行设备备份恢复。

限定本地检查选择 `Environment,Publish,Consumers,PublicationArtifacts`，仅验证六个独立消费者、实际 Manifest 合并、原始文档／Javadoc 编译和产物。新发布文档身份及新 P5 定义的结果须来自独立证据，不能回填为历史成功。准备阶段不运行初始化、应用、数据库、设备、Fake、测试或全量 Lint，不联网执行 P5，不提交推送、不创建标签或发布版本。下面已有结果均为历史输入证据。

各模块二进制及 sources JAR 包含 `META-INF/log-record/<module>/LICENSE`，内容应与根 MIT LICENSE 文本一致（仅允许 CRLF/LF 换行差异）。Android 二进制对应 AAR 内的 classes.jar。POM 是 Maven 消费者读取模块身份和传递依赖的描述文件，应包含正确的 group/artifact/version、项目名称、说明、项目 URL、SCM 及 MIT 许可信息。

POM 中 Gson 2.10.1 和同版本 core 保留 `compile` 范围，SQLite JDBC 3.42.0.0、Room 2.5.2、AndroidX Annotation 1.6.0 保留 `runtime` 范围；Android Kotlin BOM 1.8.0 保留 `type=pom、scope=import`。Android 库另以 `runtimeOnly` 显式声明 `kotlin-stdlib-jdk7:1.8.0`、`kotlin-stdlib-jdk8:1.8.0`，在 POM 中生成同版本的 `runtime` 依赖，以补齐原有 1.8.0 对齐契约；Maven 消费者不手动添加 BOM、不使用 `force`。源码包通过 `sources` classifier 获取 `<模块名>-<版本>-sources.jar`，不再通过 `.module` 的源码变体寻址。

这些包内 MIT 文件适用于本库原创代码，不把依赖重新许可为 MIT。三个二进制、三个 sources、三份 POM、`.module` 和重定向标记缺席，以及实际产物 SHA-256 都必须由本轮检查确认，不能只检查构建脚本文本。

- `exportLogs` 和 `exportExceptions` 同步执行，回调在调用线程触发。Android 业务方负责在后台执行数据库和文件操作。
