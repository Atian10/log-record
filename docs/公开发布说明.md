未来另获 Git 交付及 P5 授权后，按以下顺序验收；不重复请求旧提交来假装修复：

1. 固定包含本次修复的**新完整提交 SHA**，核对发布输入与提交内容一致，保存源码指纹。首先以精确提交版本验收，核对远端日志中的完整 SHA、版本、Gradle 7.5、JVM 11、三个发布任务及构建结果。
2. 检查三个 POM 的模块坐标、版本、项目及许可信息、依赖范围、Kotlin BOM import，以及 Android 显式发布的 jdk7/jdk8 1.8.0 runtime 依赖。下载三个 JAR/AAR 与 `sources` classifier 制品，保存请求地址、响应状态、实际来源及原始字节 SHA-256。目标 `.module` 必须返回 HTTP 404，POM 必须没有 Metadata 重定向标记；403、超时、服务器错误或只忽略 `.module` 都不能算通过。
3. 逐条比较源码包与目标提交中的 Java 源码原始字节，记录缺失、额外、重复和生成条目，区分源码内容哈希与压缩包哈希；生成文件单列来源。脚本或明确记录的辅助复核必须完成这些内容，不能仅凭存在 Java 文件省略对应检查。
4. 以 `DefaultMaven`（真正默认，不设置 `metadataSources`）和 `PomOnly`（`mavenPom()` 加 `ignoreGradleMetadataRedirection()`）各跑 core、Desktop、Android，共六个独立验收单元。这是新 POM 发布策略的验收，不是原 `ModuleOnly/PomOnly` 通过；两模式都要完成传递依赖、源码和 Kotlin BOM 检查。
5. 每个单元使用独立工程及独立、初始为空的 Gradle 缓存。本库 group 排他从 JitPack 取得；其他依赖可用 Google/Maven Central。本库不得回退到其他仓库、`mavenLocal`、本地测试仓库、`flatDir`、复合构建或旧缓存。保存实际依赖图、制品 URL／仓库来源、缓存路径和哈希。
6. 核对 Gson 2.10.1、SQLite JDBC 3.42.0.0、Room 2.5.2、Annotation 1.6.0，以及 Kotlin BOM、最终 stdlib/jdk7/jdk8 均为 1.8.0。BOM 记录为 POM／版本约束证据，不要求不存在的 BOM JAR；消费者不手动补 BOM 或强制版本。Java 仅编译及核对依赖图；Android 仅 Debug／Release、R8、依赖图、包内 MIT、Java 11 字节码和 consumer rules 检查，不运行应用或数据库。
7. 精确提交全部通过后，才能为该**提交版本**提供已验证坐标。若以后另获候选标签发布授权，再确认标签指向同一完整 SHA，并以标签版本及新的六组空缓存重复验证；未经标签验证不宣称标签可用。当前不创建、推送或验证新标签，也不发版。

客户端取消、断网、超时或停止本地脚本，不保证 JitPack 已停止远程构建。应记录请求、时间、最后状态和未知结果；不能把取消写成远程停止，也不能把缺少日志、哈希或消费者结果写成通过。

本轮不执行真机、模拟器、ADB、应用安装或运行、初始化方法、Room/真实业务数据库执行、正式签名、应用商店验收、SDK/JDK/依赖工具安装、凭据读取、全局环境修改、远程 JitPack 请求、Git 提交/推送/标签、仓库可见性变更、Release 发布。P4 的构建可使用隔离的临时调试签名材料，不接触正式签名。
